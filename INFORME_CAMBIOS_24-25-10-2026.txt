2) PERFORMANCE - Timeout de VCT_MAIN_PROYECTOS (24/10)
================================================================================
Problema: la pantalla Proyectos caía en "Execution Timeout Expired".
Causa: usaba una función escalar (VCT_HTML_ESC) por cada fila (~13k llamadas) y
       columnas VARCHAR(MAX) concatenadas en FOR XML (LOB = lento).
Fix:   se eliminó la UDF escalar (REPLACE inline + UPDATE set-based) y se pasaron
       las columnas a VARCHAR(4000). Resultado ~250 ms.                      [OK]
Diagnósticos usados: DIAG_PROYECTOS_TIMEOUT (v1-v4), DIAG_PROYECTOS_DEF,
                     DIAG_PROYECTOS_TIEMPO.

3) FLASH / FOUC EN TODA LA SPA (el tema grande, 25/10)
================================================================================
Síntoma: al tocar cada solapa, la pantalla "flasheaba" (se veía la tabla cruda
y después se montaban estilos/toolbar/paginado). Notorio en Proyectos,
Empleados, Consultores; también en Calendario; Inicio/Acciones casi no se
notaban (grilla abajo o pantalla liviana).

Causas (varias sumadas), diagnosticadas en vivo con el navegador:
  a) El commit de tooltips (22/10) infló vct-datagrid.css (+889) y
     vct-datagrid.js (+654). Archivos enormes, servidos SIN compresión y SIN
     cache -> el CSS llegaba después del paint = FOUC en cada pantalla.
  b) El motor del datagrid inicializaba en setTimeout(0) -> la tabla cruda
     (todas las filas, sin toolbar) se pintaba y recién después se
     reestructuraba (reshape visible).
  c) VCTColStd (en vct-datagrid.js) reescribía el <colgroup> de las tablas 360
     con setTimeout(...,60) -> salto de anchos post-paint (se midió: la columna
     Proyecto saltaba +43px a los ~81 ms).
  d) El calendario inyectaba vct-datepicker.css?v=20 (hardcodeado en JS),
     distinto del v50 del head -> doble carga tardía en Calendario.

Fixes aplicados:
  - vct-datagrid.js: init del motor y VCTColStd pasados a MICROTASK
    (Promise.resolve().then) -> corren ANTES del primer paint. Ya no se ve la
    tabla cruda ni el reshape de columnas.                                   [EN PR #13]
  - vct-datagrid.css: ANTI-FLASH. Mientras la grilla no está lista
    ([data-vct-dg]:not([data-vct-dg-ready="1"])) se oculta y muestra un
    spinner (aparece recién a los 250 ms). Cuando el motor termina, aparece la
    grilla ya armada. Verificado en vivo en Proyectos: 1ra pintura ya sale
    armada, 0 saltos (las 862 filas crudas nunca se ven).                    [EN PR #13]
  - main/Default.aspx: head datagrid.css?v=51.                              [EN PR #13]
  - DATAGRID_BUMP_V51.sql: bump de datagrid.css + datagrid.js a v51 en los SP. [EN PR #13]
  - web.config del server: ver sección 6.                                    [SERVER]
  - vct-calendario.js (server): datepicker.css?v=20 -> ?v=50 (cierra el último
    FOUC, el de Calendario).                                                 [SERVER/OK]

Fixes previos relacionados del 25/10 (ya commiteados):
  - Precargar CSS de grilla + de cada pantalla en el <head> de Default.aspx.

5) TOOLTIPS - Vista 360 de Consultor (25/10)
================================================================================
Problema: el tooltip del calendario del V360 de Consultor NO mostraba proyecto
ni servicios, cuando sí andan en la Agenda del consultor.
Causa: VCT_MAIN_CONSULTORES_V360 arma el JSON de días (@V360_AGC_DIAS) SIN las
       claves "proy"/"srv" (el render JS ya sabe mostrarlas).
Fix:   CONSULTOR_V360_DIAS_PROYSRV_V1.sql -> calca en el V360 el mismo
       enriquecimiento (OUTER APPLY: visita asignada ese día -> proyecto +
       servicios) que ya tiene VCT_MAIN_AGENDA_CONSULTOR. Re-ejecutable,
       falla-seguro.                                                         [EN PR #13 / falta correr]
Diagnóstico usado: DIAG_DIAS_PROY_SRV.sql.

6) SERVER - web.config (compresión + caché) (25/10)
================================================================================
Estado real (confirmado por headers HTTP en vivo):
  - urlCompression doStaticCompression="true": gzip ANDA (css 121KB -> 24KB).
    OJO: IIS comprime recién del 2do hit de cada archivo (frequentHitThreshold),

(Ctrl+Shift+R). OJO: algunos assets se cargan SIN ?v (vct-main.css, vct-shell.css,
vct-calendario.js) -> esos solo se actualizan con hard-reload o esperando 1 día.
